Вход. Литерал — переменная или её отрицание, клауза — дизъюнкция литералов, КНФ — конъюнкция клауз. Вопрос: есть ли набор значений переменных, при котором истинна каждая клауза. 3-SAT NP-полна (Кук, Левин). В примере выполняющий набор единственный: первые две клаузы дают x1 ≠ x2; при x2 = 1 последние две клаузы требуют и x3, и ¬x3; значит, x1 = 1, x2 = 0, и третья клауза даёт x3 = 1. Проверить набор легко — подставить; найти трудно. Внизу та же формула в формате DIMACS: строка p cnf n m, затем по строке на клаузу, минус — отрицание, 0 — конец клаузы. В этом формате записаны 80 формул задачи A.

Практика. CDCL-решатели (обучение клаузам на конфликтах; с конца 1990-х: GRASP, Chaff, MiniSat, сейчас CaDiCaL, Kissat) решают промышленные формулы с миллионами переменных и клауз: верификация процессоров и программ, планирование, криптоанализ. На них держатся и компьютерные доказательства в математике: проблема пифагоровых троек (Heule, Kullmann, Marek, 2016; доказательство около 200 ТБ), гипотеза Келлера в размерности 7 (2020). При этом случайные 3-КНФ на пороге выполнимости (m ≈ 4,26n) трудны уже при нескольких сотнях переменных — такие формулы и получит агент в задаче A.

Теория. Перебор — 2n. Paturi, Pudlák, Zane (1997): 2(1−1/k)n; Schöning (1999): (2 − 2/k)n; PPSZ (1998, журнальная версия 2005): 2(1−μk/(k−1))n, где μk → π²/6. Для 3-SAT рекорды — 1,308n для вероятностных алгоритмов и 1,328n для детерминированных. Все эти оценки имеют вид 2(1−c/k)n: выигрыш над перебором убывает с ростом k. Для подсчёта решений (#k-SAT) было известно 2n−Ω(n/k).

Гипотезы. ETH (Impagliazzo, Paturi, 1999): существует δ > 0, при котором 3-SAT нельзя решить за 2δn; с леммой о разреживании (Impagliazzo, Paturi, Zane, 2001) это то же, что «3-SAT нельзя решить за 2o(n)». SETH сильнее: для любого ε > 0 найдётся k, при котором k-SAT нельзя решить за 2(1−ε)n; SETH ⇒ ETH ⇒ P ≠ NP. Это главные предположения условных нижних оценок: в параметризованной сложности (например, Clique нельзя решить за f(k)·no(k) при ETH) и в fine-grained сложности (например, edit distance нельзя посчитать за n2−ε при SETH).

Октябрь 2026. 26 октября OpenAI выложила в репозиторий openai/math препринт «The Exponential Time Hypothesis is False» (автор — «OpenAI»; в статье: 17 октября, редакция 25 октября): детерминированный алгоритм точно считает выполняющие наборы k-КНФ за (n+m)Ok(1)·2Ok(n log log n/√log n) с полиномиальной памятью; Lean-формализация доказывает чуть более слабую оценку 2O(n (log log n)²/√log n). Через несколько часов Anthropic выложила в anthropics/formal-math статью «A 2o(n) Time Algorithm for 3-SAT», автор — «Claude (Anthropic)», с той же по сути оценкой и Lean-доказательством (сборка около 8 минут). По тексту статьи, основной алгоритм нашла 16 октября внутренняя исследовательская модель Claude: 14 млн выходных токенов, без участия человека; люди помогали с изложением. Независимую проверку организуют Импальяццо и Патури — авторы ETH — и Райан Уильямс.

Что следует. Если результат верен, опровергнуты ETH, SETH, Gap-ETH и #ETH, а с ними основания сотен условных нижних оценок (по подсчёту в статье Claude — больше 800 статей); гипотеза об ортогональных векторах не опровергнута. Практического ускорения нет: по оценке в статье Claude, при m = 5n выигрыш над 2n начинается только при n > 1010 000. Вопрос P vs NP не затронут.

The agent loop in code

messages = [{"role": "user", "content": task}]
while True:
    reply = query_lm(messages)
    messages.append({"role": "assistant",
                     "content": reply})
    command = parse_action(reply)
    if command == "exit":
        break
    result = execute_action(command)
    messages.append({"role": "user",
                     "content": result})

query_lm
one API request with the whole history

parse_action
finds the one bash-action block in the reply

execute_action
runs it in a shell, returns stdout + stderr

The command gets the program’s access to files and network.

Простейшая модель: шаги независимы, ошибка на любом шаге губит задачу. Тогда вероятность успеха экспоненциально падает с длиной: при 95% на шаг задача из 40 шагов удаётся в 13% случаев. Question 2

40 steps, each right with probability 0.95. After each step, a check; if it fails, the agent retries the step.

(a) The check catches every error; up to 3 tries per step, each right with probability 0.95.
(b) The check catches 90% of errors; unlimited tries.

(a) (1 − 0.05³)40 ≈ 0.995, against 0.13 without checks.

(b) A step ends right with probability 0.95 / (0.95 + 0.005) ≈ 0.9948, so 0.994840 ≈ 0.81.

Retries are cheap. The errors the check misses set the ceiling.

27:30–30:30 · 3 мин.

Открыть в боте /q 2. Полторы минуты на счёт, затем раскрыть.

(a) Шаг проваливается, только если все три попытки ошибочны: 0,05³ = 1,25·10⁻⁴. Тогда (1 − 1,25·10⁻⁴)⁴⁰ ≈ 1 − 0,005 ≈ 0,995.

(b) Каждая попытка: верна с вероятностью 0,95; ошибочна и поймана — 0,045 (повтор); ошибочна и не поймана — 0,005 (тихий провал). Шаг кончается верно с вероятностью 0,95/(0,95 + 0,005) ≈ 0,9948, задача — 0,9948⁴⁰ ≈ 0,81. Даже с бесконечным числом попыток потолок задаёт доля ошибок, которые проверка пропускает.

Допущения модели — проговорить до счёта.

1. Попытка — это одно выполнение шага. Каждая попытка верна с вероятностью 0,95, независимо от других попыток и других шагов. Повтор — новая попытка того же шага, а не исправление старой: она снова ошибается с вероятностью 0,05.

2. Проверка запускается сразу после попытки. Ложных тревог нет: верную попытку она всегда пропускает. Пойманная ошибка полностью откатывается, и следующая попытка начинается с того же состояния.

3. Ошибка, которую проверка пропустила, губит задачу: дальше её никто не ловит. Задача удалась, если все 40 шагов закончились верной попыткой.

Зачем в (a) три попытки, если проверка ловит всё? Проверка находит ошибку, но не исправляет её: исправить может только следующая попытка, а она тоже может ошибиться. Три попытки — бюджет на шаг. Если все три ошибочны (вероятность 0,05³), шаг не сделан, агент останавливается, и задача не удалась. При идеальной проверке и неограниченном числе попыток успех был бы гарантирован, в среднем за 1/0,95 ≈ 1,05 попытки на шаг. Пункт (a) показывает, что даже маленького бюджета хватает: 0,995 против 0,13. Пункт (b) — обратный случай: попыток сколько угодно, но проверка неполна, и тогда потолок задаёт доля пропущенных ошибок. В среднем в (b) нужно 1/(1 − 0,045) ≈ 1,05 попытки на шаг.

В жизни эти допущения нарушаются. Ошибки коррелированы: модель с тем же контекстом склонна повторить ту же ошибку, поэтому полезно менять подход, а не просто повторять. Проверка бывает и с ложными тревогами, и тогда агент тратит бюджет на исправление верного. Откат не всегда возможен: удалённый файл или отправленное письмо не вернуть.

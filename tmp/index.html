The agent loop

An LLM, tools and a while loop

Сначала напишем агента сами, затем заглянем внутрь настоящего.

What is an agent?

An LLM agent runs tools in a loop to achieve a goal.

Simon Willison, September 2025

Chat

The model writes a reply.

+ Tool use

The model writes a tool call; the program runs it.

+ Loop

The result goes back into the context; the model chooses the next call.

“To achieve a goal”: the loop needs a way to stop.

The agent loop in code

messages = [{"role": "user", "content": task}]
while True:
    reply = query_lm(messages)
    messages.append({"role": "assistant",
                     "content": reply})
    command = parse_action(reply)
    if command == "exit":
        break
    result = execute_action(command)
    messages.append({"role": "user",
                     "content": result})

query_lm
one API request with the whole history

parse_action
finds the one bash-action block in the reply

execute_action
runs it in a shell, returns stdout + stderr

The command gets the program’s access to files and network.

Adapted from the Minimal AI agent tutorial · full version: materials/agent.py

10:30–13:00 · 2.5 мин.

Пройти код построчно. История сообщений растёт: запрос, ответ модели, результат команды, снова ответ — это и есть контекст из лекции 3, и он пересылается целиком на каждом шаге. Результат команды отправляется с ролью user — так устроен учебный текстовый протокол; в API с tool calling для этого есть отдельный тип блока tool_result.

Спросить: какие строки делают программу агентом? Существенны две вещи: модель выбирает следующее действие, а результат действия возвращается в её вход. Сам while встречается в любой программе.

Справа — три функции. Подчеркнуть последнюю строку: модель только пишет текст; доступ к диску и сети появляется в execute_action, и он ровно такой, как у запущенной программы. Ограничения (песочница, разрешения) задаются здесь, а не в промпте. Подробно — в лекции 5.

An agent, formally

  • Environment state st: files, processes, web pages. The model does not see it.
  • Action at: a tool call. Observation ot: its result.
  • History ht = (goal, a1, o1, …, at−1, ot−1) — this is the context.
  • The LLM is a stochastic policy πθ(at | ht) with fixed weights θ.
  • The harness defines the actions, what goes into ot, the budget and when to stop.

A partially observed decision process. What is not in the context does not exist for the agent.

17:00–19:00 · 2 мин.

Для этой аудитории полезна формальная рамка. Это POMDP: состояние среды скрыто, агент видит только наблюдения. Стратегия зависит от всей истории — и история здесь буквально равна контексту модели. Стохастичность — из выборки токенов (температура, лекция 2).

Следствия. (1) Агент ничему не учится в процессе: веса θ фиксированы, меняется только вход (лекция 2). (2) Всё, что агент «знает» о среде, попало в контекст через наблюдения; если наблюдение обрезано или сжато при компактизации (лекция 3), для стратегии этого нет. (3) Обвязка определяет пространство действий и функцию наблюдения — одна и та же модель с разными инструментами и выводом ведёт себя по-разному.

Why agents work

Feedback, checking and its limits

Почему цикл с обратной связью вообще справляется с длинными задачами, и где он ломается.

Errors compound over long tasks

25:00–26:30 · 1.5 мин.

Простейшая модель: шаги независимы, ошибка на любом шаге губит задачу. Тогда вероятность успеха экспоненциально падает с длиной: при 95% на шаг задача из 40 шагов удаётся в 13% случаев. Настоящий агент делает десятки и сотни шагов (у Claude Code в нашей демонстрации — десяток, у компилятора C в разделе 3 — тысячи сессий).

Модель грубая: шаги не независимы, и не каждая ошибка фатальна. Но она объясняет, почему без обратной связи длинные задачи не решаются, — и задаёт следующий вопрос.

Question 2

40 steps, each right with probability 0.95. After each step, a check; if it fails, the agent retries the step.

(a) The check catches every error; up to 3 tries per step.
(b) The check catches 90% of errors; unlimited tries.

(a) (1 − 0.05³)40 ≈ 0.995, against 0.13 without checks.

(b) A step ends right with probability 0.95 / (0.95 + 0.005) ≈ 0.9948, so 0.994840 ≈ 0.81.

Retries are cheap. The errors the check misses set the ceiling.

26:30–29:30 · 3 мин.

Открыть в боте /q 2. Полторы минуты на счёт, затем раскрыть.

(a) Шаг проваливается, только если все три попытки ошибочны: 0,05³ = 1,25·10⁻⁴. Тогда (1 − 1,25·10⁻⁴)⁴⁰ ≈ 1 − 0,005 ≈ 0,995.

(b) Каждая попытка: верна с вероятностью 0,95; ошибочна и поймана — 0,045 (повтор); ошибочна и не поймана — 0,005 (тихий провал). Шаг кончается верно с вероятностью 0,95/(0,95 + 0,005) ≈ 0,9948, задача — 0,9948⁴⁰ ≈ 0,81. Даже с бесконечным числом попыток потолок задаёт доля ошибок, которые проверка пропускает.

Допущения: ошибки независимы, проверка срабатывает сразу после шага и не даёт ложных тревог. В жизни ошибки коррелированы (модель повторяет ту же ошибку), поэтому полезно менять подход, а не просто повторять.

Эксперимент Николаса Карлини: 16 экземпляров Claude параллельно, каждый в своём контейнере в бесконечном цикле, общий git-репозиторий. 76:00–83:00 · 7 мин. Открыть в боте /q P. Группы по 2–3 человека, 5 минут; одно сообщение от группы.

Напомнить термин: гамильтонов цикл проходит через каждую вершину ровно один раз. Нужно спроектировать агента, а не решить задачу руками (но кто решит — молодец).

Вариант для групп, у которых есть идея проекта: та же карточка для своей задачи — особенно строка «кто проверяет».

A reference answer

Tools
Python; generate all graphs on n vertices (networkx, or nauty’s geng); a Hamiltonicity test (dynamic programming over subsets, O(2ⁿ n²))
Checker
a separate 20-line script: connected, minimum degree ≥ 2, no Hamiltonian cycle — run on the returned graph
Budget, stopping
n ≤ 10, ten minutes; stop at the first checked counterexample
What can go wrong
a bug in the Hamiltonicity test; reporting “none up to n = 8” as a proof
A person checks
reads the checker and looks at the drawing

A counterexample: two triangles sharing a vertex. The shared vertex is a cut vertex.

83:00–86:00 · 3 мин.

Разобрать 2–3 ответа из бота, затем показать эталон. Главное — независимый проверяющий: короткий скрипт, который легко прочитать человеку, отдельно от кода поиска. Тогда ошибка в поиске не превратится в ложный «контрпример».

Контрпример: «бабочка» — два треугольника с общей вершиной, 5 вершин. Граф связный, у всех вершин степень ≥ 2, но общая вершина — точка сочленения: цикл не может обойти обе половины, не пройдя её дважды. Любой граф с точкой сочленения — контрпример.

Различать три исхода: найден и проверен контрпример; поиск остановлен по бюджету; в исследованном диапазоне контрпримера нет. Третий исход не доказывает гипотезу — как и «10 000 проверенных случаев».

What to remember

  1. An agent is an LLM, tools and a loop. The loop fits in a hundred lines.
  2. Its state is its context: what is not in the context does not exist for it.
  3. Feedback turns pn into near-certainty — if the checker is good.
  4. Agents satisfy weak checkers instead of goals: check the artifact, not the report.
  5. Limits and budgets are enforced outside the model.
